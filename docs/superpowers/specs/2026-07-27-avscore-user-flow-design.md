# avscore 用户端两步流程设计

## 目标

将当前“一键生成静态画像”的演示完善为真实可用的本地两步流程：

1. 用户从本机已同步的 Agent 会话中选择一个 session。
2. 系统分析该 session 所属项目，并展示 7D AI 协作画像。

同时完善根目录 `README.md`，并增强 `avscore` skill 与启动脚本的安全性、兼容性和错误可恢复能力。

## 范围与明确限制

- 选择页读取 `agentsview session list --format json` 返回的真实 session。
- 当前 `agentsview profile` 仅支持 `--project`，不支持按单个 session 过滤。因此选择 session 是用户入口，实际画像范围是该 session 所属项目的所有可分析会话。
- 选择页、分析中状态和结果页都必须明确显示项目级分析范围，不使用容易让用户误解为“单 session 画像”的文案。
- 不修改上游 `agentsview` 二进制，也不声称支持二进制尚未提供的功能。
- 本次不加入云端上传、账号系统、分享服务或远程分析。

## 架构

### 启动器

`avscore.sh` 负责：

1. 检测操作系统与架构。
2. 定位或下载 `agentsview` 二进制并验证。
3. 执行 `agentsview sync`。
4. 检查 Python 3。
5. 启动仅监听 `127.0.0.1`、使用随机端口和随机启动令牌的本地 UI 服务。
6. 打开带令牌的选择页 URL。
7. 在服务退出或收到信号时清理临时资源，不删除已生成报告。

### 本地 UI 服务

新增一个只依赖 Python 3 标准库的服务，负责：

- 执行 `agentsview session list --format json` 并规范化数据。
- 按 Agent 对 session 分组并提供给选择页。
- 校验浏览器提交的 session ID 必须存在于当前服务端 session 集合。
- 从服务端 session 记录中取得 project，不信任浏览器提交的 project。
- 以参数数组执行 `agentsview profile --json --engine statistical --project <project>`。
- 仅在确认旧版 CLI 不支持 `--engine` 时回退到不含 `--engine` 的命令；其他错误原样失败。
- 将画像数据映射为结果页所需模型并返回。
- 使用临时文件加原子替换保存 `profile.json`、`report.json` 和 `report.html`。

浏览器不直接访问本地文件、不执行 shell，也不能提交任意命令参数。

## 页面与交互

### 选择页

- 使用参考选择页的头部、Hero、Agent 折叠卡片、session 单选项、底部操作栏和隐私勾选。
- session 按 Agent 分组，默认展开最近有活动的第一组。
- 每条 session 展示真实标题或首条消息摘要、更新时间、消息/轮次数和所属项目。
- 用户选中 session 后，底部摘要同时显示：
  - Agent 与 session 标题。
  - 将分析的项目名称。
  - 该项目的相关 session 数。
- 未选择 session 或未勾选本地分析授权时，分析按钮禁用。
- 页面必须支持键盘操作与正确的 `aria-expanded`、表单标签和焦点样式。

### 分析中状态

- 点击分析后禁用重复提交，并显示项目名和当前阶段。
- 同一服务实例最多运行一个画像任务；并发请求返回明确的“分析正在进行”状态。
- 失败后保留原选择，显示经过安全处理的错误摘要并允许重试。

### 结果页

- 使用参考结果页的 Hero、画像类型、标签、7D 雷达图、维度详情、优势与成长建议、结尾操作区。
- 真实分数驱动雷达图与维度详情。
- 展示可信元信息：项目名、样本 session 数、生成时间、分析引擎和是否发生旧版降级。
- 提供“重新选择会话”入口。
- 对画像 JSON 中缺失的可选字段提供中性默认文案；核心分数字段无效时视为分析失败，不展示误导性结果。

### 空数据与兼容状态

- 未发现 session：说明支持的 Agent 类型，并给出自定义数据目录环境变量提示。
- sync 失败：显示失败原因，不使用不明确的旧缓存继续分析；用户可按文档显式选择跳过 sync。
- Python 3 缺失：在终端给出明确安装要求，不静默回退到不可交互的静态流程。
- 浏览器自动打开失败：终端仍打印完整本地 URL。
- 页面服务退出后，已生成的 `report.html` 仍可离线打开。

## 数据安全

- 服务仅绑定 `127.0.0.1`。
- 每个 API 请求验证随机启动令牌。
- 只接受服务端已知的 session ID。
- 子进程使用参数数组，不使用 `shell=True` 或字符串拼接。
- 所有进入 HTML 的文本均转义；JSON 响应使用标准序列化。
- 错误响应不暴露本地会话正文、令牌或完整敏感路径。
- 下载二进制时默认要求校验和；无法取得校验和时不以“已验证”文案误导用户。

## 测试与验收

### 自动化测试

- 平台与架构检测。
- 二进制查找优先级。
- session JSON 正常、空数组、字段缺失、非法 JSON。
- session ID 校验与 project 参数安全传递。
- profile 正常输出、旧版 `--engine` 降级、非兼容错误不降级、超时。
- 分析并发锁。
- HTML 转义与核心分数验证。
- 报告文件原子写入。
- HTTP token 缺失/错误、未知路由、非法请求体。
- shell 静态语法检查与关键失败路径。

### 视觉与交互验收

- 桌面和移动视口分别截图，与两份参考 HTML 对比。
- 选择、展开/收起、授权勾选、按钮禁用、失败重试、重新选择均可用。
- 页面无横向溢出，移动端操作栏不遮挡内容。
- 支持 `prefers-reduced-motion`。
- HTML 中无未替换占位符、无 Mock session、无 KwAITI 遗留品牌文案。

## 完成标准

- 用户通过一个入口命令完成真实的选择与分析流程。
- 页面样式与两份参考 HTML 保持一致。
- 页面明确披露分析范围是所选 session 的所属项目。
- README、skill、启动脚本和实现相互一致。
- 自动化测试通过，且桌面/移动端视觉检查无阻断问题。
