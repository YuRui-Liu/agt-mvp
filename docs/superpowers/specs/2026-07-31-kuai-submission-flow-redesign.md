# kuAI C 端提交闭环重设计

## 1. 目标

将 C 端流程收敛为：

选择 Assessment Scope → 本地逐 session 准备 → 手机验证 → 用途授权 → 安全上传 → 提交成功。

上传确认成功是用户可见终点。服务端可继续后台分析，但 C 端不再轮询或展示分析状态、画像、评分、海报下载入口。

## 2. 已批准方案

采用方案 A：就近准备 + 独立状态切屏。

- 准备、验证和授权反馈紧贴用户当前选择。
- 上传阶段使用独立页面，避免长列表和表单干扰。
- 上传成功后使用独立感谢页面。
- 不伪造无法从接口获得的上传百分比。

## 3. 选择与准备页面

### 3.1 默认状态

- Scope 默认不选中。
- 页面展示可选择 Scope 和不可选择的检测结果。
- Scope 卡片只展示安全元数据。

### 3.2 大小显示

- `bytes > 0` 时使用统一格式显示 B、KB、MB 或 GB，最多一位小数。
- `bytes` 缺失、非数值、为零或小于零时，整个大小字段不渲染。
- 页面不得出现“大小未知”。
- 当前版本不通过额外文件扫描或估算制造预测值。

### 3.3 就近插入

用户选择 Scope 并完成本地准备后：

- “逐 session 准备”卡片插入到所选 Scope 卡片正上方。
- 手机验证和用途授权紧随准备卡片排列。
- 不再将这些卡片固定渲染在完整 Scope 列表底部。
- 开始新提交或更换 Scope 时，清理旧准备状态和旧插入位置。

## 4. 安全上传页面

### 4.1 页面结构

点击“确认并安全上传”后，隐藏选择流程，展示独立上传页面：

- 顶部为 kuAI 品牌标识。
- 中央为原创的安全上传装饰，不复用参考图水印素材。
- 标题为“正在安全上传数据”，其中“上传数据”使用橙色。
- 说明用户保持页面打开。
- 展示阶段进度条和三步清单：
  1. 加密所选会话数据；
  2. 上传至远端存储；
  3. 校验提交结果。
- 底部说明仅上传用户主动勾选并已脱敏的数据。

### 4.2 进度真实性

当前 `/api/tasks` 一次完成创建、上传和确认，不能提供真实字节百分比。因此：

- 不展示 `38%` 等伪造精确百分比。
- 使用阶段状态和非精确动画进度。
- 步骤必须同时通过图标、文字和 ARIA 状态表达，不只依赖颜色。
- 请求成功时完成第三阶段并进入成功页面。

### 4.3 错误恢复

- 上传失败后展示明确错误并允许使用原幂等键安全重试。
- 重试时恢复上传页面，不重复创建用户不可控的提交。
- “重新开始”会清理上传、认证、授权和准备状态。
- 所有主要操作按钮在请求期间禁止重复触发。

## 5. 提交成功页面

### 5.1 用户可见终态

收到上传任务创建、上传和确认成功的响应后，立即展示提交成功页：

- 不再启动任务状态轮询。
- 不展示“分析中”。
- 不展示画像、评分、维度或海报。
- 刷新后的恢复逻辑不得把用户带入旧画像流程。

### 5.2 视觉结构

桌面端使用居中的白色大圆角容器：

- 顶部左侧为 kuAI 品牌，右侧为带对勾的“提交成功”状态。
- 左侧主标题分两行：“谢谢你，”为黑色，“提交成功！”为橙色。
- 正文说明所选会话数据已经安全送达。
- 信息卡展示：
  - 提交内容；
  - 状态“已安全送达”；
  - 提交时间；
  - 安全的短提交编号。
- 右侧使用原创 CSS/SVG 橙色品牌装饰，不从参考截图裁切素材。
- 主按钮“返回校招职位”跳转 `/application`。
- 次按钮“再次提交”重置到初始选择状态。

### 5.3 响应式

- `≤ 700px` 时改为单列，正文在上、装饰在下。
- 信息卡从两列改为一列。
- 主标题缩小到适合窄屏的尺寸。
- `≤ 420px` 时两个按钮纵向排列并占满可用宽度。
- 页面不得产生横向滚动。

## 6. 无障碍

- 上传页面使用 `role="status"` 和 `aria-live="polite"`。
- 进度条提供 `aria-valuemin`、`aria-valuemax` 和阶段型 `aria-valuetext`。
- 当前步骤使用 `aria-current="step"`。
- 成功页面展示后，将焦点移至可聚焦的主标题。
- 成功状态保留对勾和文字，不只依赖绿色。
- 装饰图形使用 `aria-hidden="true"`。
- 错误继续使用 `role="alert"`。
- 交互控件最小高度为 44px，正文颜色满足可读性要求。

## 7. 状态机

```text
scope_selection
  -> local_preparation
  -> phone_verification
  -> consent
  -> uploading
  -> submission_success
```

失败分支：

- `local_preparation` 失败：保留选择并显示局部错误。
- `phone_verification` 失败：停留在验证阶段。
- `uploading` 失败：进入可安全重试状态。
- 只有用户点击“再次提交”才从成功页返回 `scope_selection`。

旧状态 `pending`、`analyzing`、`profile` 和 `poster` 不再属于 C 端可见状态机。

## 8. 测试要求

实现必须遵循测试先行：

1. 先增加失败测试，证明：
   - 页面不包含“大小未知”；
   - 无有效字节数时不渲染大小分隔片段；
   - 准备/认证/授权区域位于所选 Scope 卡片上方；
   - 上传时只显示独立上传页；
   - 上传页含三阶段、ARIA 状态且无伪造百分比；
   - 上传确认成功后只显示成功页；
   - 成功页不含分析、画像、评分或海报；
   - 成功页两个按钮行为正确；
   - 上传失败可以重试；
   - 刷新不会恢复旧画像流程。
2. 运行测试并确认因功能缺失而失败。
3. 实现最小代码使测试通过。
4. 执行完整前端、Go、文档和构建验证。
5. 使用桌面和移动端浏览器截图进行视觉核查。

## 9. 非目标

- 不修改服务端异步分析实现。
- 不新增真实字节级上传进度接口。
- 不重新引入海报下载。
- 不从带水印的参考截图提取或复制吉祥物素材。
- 不扩大本地文件扫描范围来估算大小。
