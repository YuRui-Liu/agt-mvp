# kuAI 本地 Agent 会话上传与分析服务 PRD

## 1. 文档信息

- 首版产品名称：`kuAI`
- 首版 CLI 名称：`kuai`
- 文档类型：产品需求与系统设计
- 首版形态：本地 Mock MVP，接口与未来正式服务保持一致
- 目标平台：macOS、Linux、Windows

## 2. 背景

现有 avscore 流程以本地分析和本地报告为核心，不上传会话。新的产品方向改为：用户通过一条命令或 Agent skill 安装 `kuai`，客户端自动扫描本机 Agent 会话，用户选择一个 Project，在本地自动脱敏后上传到服务端，获得一张包含初步分析和投递二维码的海报。

首版不依赖固定公司域名，使用可配置服务端地址和本地 Mock 服务完成演示，不向公网发送真实数据。正式环境只能通过受信任的发布配置注入服务地址。

## 3. 产品目标

首版需要验证以下完整闭环：

1. 用户能在没有开发环境依赖的设备上安装并运行 `kuai`。
2. 客户端能发现本机已有的 Agent 会话，并按 Project 组织。
3. 用户能主动选择一个 Project，而不是默认上传全部本地会话。
4. 数据离开本机前完成自动脱敏、身份验证和用途授权。
5. 同一认证主体在不同设备、多次上传时始终恢复同一个 `kuAI ID`。
6. 上传完成后生成不公开真实分数和算法细节的分析海报。
7. 用户通过海报二维码进入与本次分析关联的职位投递页。
8. Mock 环境能稳定演示正常流程及关键失败恢复。

## 4. 非目标

首版不包含：

- 用户上传历史列表；
- 用户查看已上传的原始内容；
- 用户自助删除历史数据的入口；
- 默认上传本机全部会话；
- 将未验证的 Agent 格式转换后试探性上传；
- 上传附件、完整文件副本或二进制内容；
- 向用户公开真实分数、维度权重、排名或算法细节；
- 在客户端写死未通过受信任发布配置提供的正式公司域名；
- 依赖 Python、Node、Git、WSL 或管理员权限；
- 用 skill 单独实现一套扫描、脱敏或上传逻辑。

## 5. 用户与核心场景

### 5.1 目标用户

- 使用 Claude、agentreview 或其他 Agent 完成真实项目的开发者；
- 希望获得 AI 协作能力反馈并进一步参与职位投递的候选人；
- 需要验证扫描、脱敏、分析和投递闭环的内部演示与研发人员。

### 5.2 核心场景

用户运行 `kuai` 后，在本地网页中查看已经发现的 Agent 和 Project，选择一个受支持的 Project。客户端在本机整理并脱敏数据。用户随后完成手机号验证码认证、确认数据用途并上传。服务端生成分析结果和海报，用户可以下载海报或扫描二维码投递职位。

## 6. 产品范围

### 6.1 上传粒度

- 正式用户主流程只允许选择一个 Project。
- 一个 Project 上传包可以包含该 Project 下多个受支持的 session。
- 单 session 上传只用于开发调试，通过显式调试开关开放，默认不出现在用户界面。
- 客户端不得自动选择 Project，也不得在用户操作前上传任何会话内容。

### 6.2 Agent 支持策略

- 扫描层动态展示 `agentsview` 实际识别到的 Agent，不在产品界面硬编码完整名单。
- 首版允许上传 Claude 和 agentreview 当前已验证的原始会话格式。
- 已发现但未通过服务端分析验证的 Agent 仍显示在列表中，并标记为“已检测，暂不支持上传”。
- 未支持的 Agent 和 Project 不可选择、不可上传。
- 后续通过新增来源适配器逐步支持主流国内外智能体。

## 7. 安装与启动

### 7.1 安装入口

macOS 和 Linux 提供一条 Shell 安装命令，Windows 提供一条 PowerShell 安装命令。两种安装器具有相同行为：

1. 检测操作系统和 CPU 架构。
2. 解析明确的客户端版本。
3. 下载对应的 `kuai` 可执行文件和校验信息。
4. 验证 SHA-256；正式发布阶段增加产物签名验证。
5. 原子安装到当前用户目录。
6. 在不请求管理员权限的前提下配置或提示 PATH。
7. 重复执行时安全升级或保持当前版本。

任何下载、版本解析、校验或替换失败都必须保留已安装版本。

### 7.2 Skill 入口

Agent skill 只负责：

1. 检查 `kuai` 是否已安装。
2. 未安装时调用与命令行用户相同的可信安装器。
3. 运行 `kuai`。
4. 说明用户需要在打开的本地页面中完成选择、认证和上传。
5. 对失败提供安全、可操作的说明。

skill 不得复制临时扫描器、脱敏器或上传脚本，也不得绕过产物校验。

### 7.3 平台矩阵

首版目标：

- macOS Apple Silicon；
- macOS Intel；
- Linux `arm64`；
- Linux `amd64`；
- Windows 10/11 `x64`；
- Windows `arm64` 构建与安装验证。

用户不需要预装 Python、Node、Git 或 WSL。

## 8. 系统架构

### 8.1 安装与入口层

安装脚本和 skill 最终安装并运行同一个 `kuai` 客户端，避免形成多套业务实现。

### 8.2 本地 `kuai` 客户端

客户端负责：

- 扫描 Agent 会话；
- 将 session 归属到 Project；
- 判断来源格式是否受支持；
- 生成 Project 上传包；
- 执行本地自动脱敏；
- 启动并保护本地 Web UI；
- 管理认证跳转和短期凭证；
- 执行可重试、幂等的上传；
- 展示任务状态和海报。

本地 HTTP 服务只监听 `127.0.0.1` 的随机端口，并使用每次启动生成的高强度令牌保护页面和接口。

Mock MVP 可以编排现有 `agentsview` 能力以缩短验证周期。正式发布目标是将核心扫描和上传能力收敛到单一原生 `kuai` 可执行文件。

### 8.3 服务端接口边界

客户端只依赖稳定的服务接口，不依赖具体域名。接口边界包括：

- 手机验证码认证；
- 认证主体与 `kuAI ID` 映射；
- 上传任务创建和分片或整体上传；
- 分析任务状态；
- 海报获取；
- 投递关联令牌签发；
- 职位投递提交。

正式服务地址由受信任配置或发布配置注入。客户端不接受页面传入任意上传地址。

### 8.4 本地 Mock 服务

首版默认使用本机 Mock 服务实现与正式服务一致的接口契约：

- 不发送真实短信；
- 不访问公网；
- 不将真实会话数据写入远程系统；
- 支持固定测试验证码；
- 支持生成和恢复 Mock `kuAI ID`；
- 支持 Mock 上传、分析、海报和投递关联；
- 支持确定性触发验证码错误、上传中断、分析失败、超时转异步和安全重试。

Mock 临时数据写入受控临时目录，演示环境可整体清理。

## 9. 端到端用户流程

```text
安装并运行 kuai
→ 扫描本机 Agent
→ 按 Agent 和 Project 展示结果
→ 用户选择一个受支持的 Project
→ 本地构建上传包并自动脱敏
→ 用户完成手机号验证码认证
→ 创建或恢复唯一 kuAI ID
→ 用户确认三类数据用途
→ 上传脱敏后的 Project 数据
→ 同步等待或转为异步分析
→ 返回并下载分析海报
→ 扫码进入关联投递页
```

### 9.1 扫描与选择

页面按 Agent 和 Project 分组。每个 Project 至少显示：

- Agent 来源；
- 项目名称或经过保护的路径别名；
- 最近活动时间；
- session 数量；
- 格式支持状态。

已验证格式允许选择；未支持格式可见但不可选择。页面不得默认选中任何 Project。

### 9.2 本地脱敏

用户选定 Project 后，客户端在本机生成上传包并处理所有允许上传的文本字段。页面可以展示：

- 处理进度；
- 纳入的 session 数量；
- 脱敏替换总数；
- 处理成功或失败状态。

页面和日志不得显示敏感原文。脱敏器报错、崩溃或无法完成处理时必须停止上传。

### 9.3 身份认证

脱敏成功后才进入手机号验证：

1. 浏览器打开认证流程。
2. 手机号由短信认证服务处理。
3. 业务服务只接收稳定认证主体 ID。
4. 首次验证时创建唯一 `kuAI ID`。
5. 后续使用同一认证主体时恢复同一 `kuAI ID`。

同一用户跨设备和多次上传时不得生成多个业务身份。

### 9.4 用途授权

上传按钮前必须清楚说明数据将同时用于：

1. 生成用户的分析海报；
2. 用户扫码投递后的候选人评估；
3. 模型和分析算法改进。

用户主动确认后才能上传。服务端记录授权文案版本、时间、认证主体和对应任务。

### 9.5 上传与分析

页面展示与真实任务对应的状态：

1. 准备上传；
2. 上传中；
3. 分析中；
4. 生成海报；
5. 完成或失败。

分析在 30 秒内完成时直接展示结果。超过 30 秒时任务转为异步，用户可关闭页面；再次完成身份验证后，可以恢复该 `kuAI ID` 关联的最新任务。首版不展示完整上传历史列表。

### 9.6 海报与投递

结果是一张可下载的图片海报，包含：

- `kuAI` 品牌；
- `kuAI ID` 的安全展示形式；
- 初步定性分析；
- 鼓励性话术；
- 不含真实数值的能力标签；
- 与本次分析关联的投递二维码。

海报不得展示真实分数、排名、维度权重、判定阈值或可用于逆向算法的细节。

二维码携带短期、一次性的投递关联令牌，不直接包含内部 `kuAI ID`。扫码后进入职位投递页；提交后，服务端将职位、候选人身份和本次分析结果建立可信关联。

## 10. 上传数据边界

### 10.1 允许上传

Project 上传包可以包含：

- 来源 Agent；
- Project 标识和必要时间元数据；
- 用户与 Agent 的文本消息；
- 工具调用名称、参数结构和文本结果；
- 代码 diff；
- Claude 和 agentreview 已验证来源格式中的必要原始事件语义。

这里的“原始事件语义”表示尽量保留来源数据结构，不表示允许上传未经脱敏的数据。

### 10.2 禁止上传

上传包不得包含：

- 附件；
- 完整文件副本；
- 二进制内容；
- 未经验证的 Agent 数据；
- 本地脱敏前的副本；
- 脱敏器无法确认已经处理完成的数据。

### 10.3 自动脱敏

客户端对允许上传的所有文本字段执行自动脱敏。至少覆盖：

- API Key、访问 Token 和会话凭证；
- 私钥和证书密钥材料；
- 邮箱、手机号等直接身份信息；
- 本地用户名和绝对路径；
- 常见云服务、数据库和代码托管凭证。

命中内容使用类型化占位符替换，例如 `[REDACTED_TOKEN]`、`[REDACTED_EMAIL]`。脱敏不要求用户逐条确认，也不得把敏感原文用于遥测或错误日志。

## 11. 数据保留与用途

### 11.1 服务端保留

- 脱敏后的完整 session 上传包保留 30 天，用于分析重算和故障排查，期满自动删除。
- 结构化特征、分析结果、授权记录及其与 `kuAI ID` 的关系长期保留。
- 长期数据可用于海报生成、候选人评估和模型或分析算法改进。
- 首版用户端不提供历史回看或自行删除入口。

即使用户界面没有历史和删除入口，服务端仍必须具备到期清理、内部审计、授权版本追踪和按合法流程执行数据处置的能力。

### 11.2 身份数据

- 手机号由认证服务处理。
- 业务服务只保存稳定认证主体 ID 与 `kuAI ID` 的映射。
- 验证码、手机号和认证临时凭证不得进入会话上传包、海报或业务日志。

## 12. 安全要求

### 12.1 本地安全

- 本地服务只绑定回环地址。
- 页面和 API 使用随机启动令牌鉴权。
- 浏览器只能选择客户端当前扫描结果中真实存在且受支持的 Project。
- Project 路径和命令参数由本地服务从可信记录确定。
- 子进程调用使用参数数组，不拼接 shell 命令。
- 页面输出经过安全编码，防止 HTML 或脚本注入。
- 脱敏失败时不存在任何网络上传。

### 12.2 远程安全

- 正式服务只允许 HTTPS。
- 手机验证码具有频率限制、有效期和失败次数限制。
- 上传使用短期授权令牌和服务端大小限制。
- 每次上传使用幂等键，重试不得创建重复上传或分析任务。
- 服务端再次检查上传包格式和高风险内容，但二次检查不能替代本地脱敏。
- `kuAI ID`、认证主体、上传任务、分析任务和投递任务通过服务端可信记录关联。
- 投递二维码令牌短期有效、一次使用，并防止篡改和重放。

### 12.3 日志安全

日志不得记录：

- 验证码；
- 完整会话正文；
- 本地绝对路径；
- 上传授权令牌；
- 本地启动令牌；
- 完整投递关联令牌；
- 被脱敏内容的原文。

## 13. 错误处理

- 不支持的平台或架构：安装前停止并明确说明。
- 下载或校验失败：停止并保留已安装版本。
- 扫描失败：指出对应 Agent 和可操作的排查方法。
- 没有受支持 Project：保持页面可访问并说明当前支持范围。
- 脱敏失败：停止上传，保留本地原始会话不变。
- 验证码错误或过期：允许重新获取，不重复扫描和脱敏。
- 上传中断：使用同一幂等键安全重试。
- 分析失败：展示安全错误摘要并允许重试，不生成伪造海报。
- 分析超过 30 秒：转为异步任务。
- 浏览器自动打开失败：在用户自己的终端提供本地访问指引，不在公开日志传播启动令牌。
- 二维码令牌过期、重复使用或被篡改：拒绝关联并引导重新获取有效海报或投递入口。

## 14. 测试与验收

### 14.1 安装

- 覆盖全部目标平台和架构。
- 覆盖首次安装、重复安装、指定版本、升级和卸载。
- 覆盖下载失败、校验失败和原子替换失败。
- 在无 Python、Node、Git、WSL 的干净环境验证。
- 测试使用临时用户目录，不污染 CI 主机。

### 14.2 扫描与选择

- 正确识别 Agent、Project 和 session 归属。
- Claude 和 agentreview 已验证格式可选择。
- 其他已识别 Agent 可见但不可上传。
- 正式入口只显示 Project 粒度选择。
- 调试开关可以显式启用单 session 上传。
- 未选择 Project 时上传流程不可继续。

### 14.3 脱敏与上传包

- 覆盖 Token、私钥、邮箱、手机号、本地路径等敏感模式。
- 验证类型化占位符替换。
- 验证附件、完整文件和二进制内容未进入上传包。
- 验证脱敏器异常时没有网络请求。
- 验证上传重试不会生成重复任务。

### 14.4 身份和授权

- 首次认证生成唯一 `kuAI ID`。
- 同一认证主体在不同设备、多次上传时恢复同一 ID。
- 验证码错误、过期、频率限制和重试符合预期。
- 未确认三类数据用途时禁止上传。
- 授权记录包含文案版本和任务关联。

### 14.5 分析、海报与投递

- 30 秒内的任务同步返回。
- 超时任务转为异步并可恢复最新状态。
- 分析失败不生成伪造结果。
- 海报可以直接下载。
- 海报包含定性分析、鼓励话术、能力标签和二维码。
- 海报不包含真实分数、权重、阈值或排名。
- 二维码不暴露内部 ID。
- 投递令牌过期、重复使用和篡改时安全失败。
- 有效二维码能够关联本次分析、候选人身份和职位。

### 14.6 Mock 演示

本地 Mock 必须完整跑通：

```text
扫描 → 选择 Project → 自动脱敏 → 手机验证 → kuAI ID
→ 用途授权 → Mock 上传 → 分析 → 海报 → 扫码投递
```

Mock 还必须能够确定性演示：

- 验证码错误；
- 上传中断和安全重试；
- 分析失败；
- 超过 30 秒转异步；
- 二维码令牌错误或重复使用。

整个 Mock 流程不得向公网发送真实数据。

## 15. 实施阶段

### 阶段一：Mock MVP

- 复用现有 `agentsview` 扫描能力。
- 建立 `kuai` 命令入口和本地 Web UI。
- 实现 Project 选择、上传包构建和自动脱敏。
- 实现本地 Mock 认证、`kuAI ID`、分析任务、海报和投递。
- 验证正常流程和关键异常。

### 阶段二：原生客户端收敛

- 将核心能力收敛为单一原生 `kuai` 可执行文件。
- 完成 macOS、Linux、Windows 多平台安装和更新。
- 固化来源适配器接口，逐步增加国内外主流 Agent。
- 增加发布签名和完整供应链校验。

### 阶段三：正式服务接入

- 保持客户端接口不变，将服务地址切换为受信任的正式配置。
- 接入真实短信认证服务。
- 接入正式分析、海报、招聘和数据生命周期服务。
- 在正式开放前完成安全、隐私、合规和数据保留审查。

## 16. 完成标准

首版完成的判定条件是：

1. 用户通过一条命令或 skill 安装并启动同一个 `kuai` 客户端。
2. 用户可以选择一个受支持的 Project，但不会默认上传任何内容。
3. 数据在本地自动脱敏，且禁止内容不进入上传包。
4. 手机认证可以创建或恢复唯一 `kuAI ID`。
5. 用户确认三类用途后才能上传。
6. Mock 服务可以完成上传、同步或异步分析并返回海报。
7. 海报不公开真实分数或算法细节，并可通过二维码进入关联投递页。
8. 关键失败场景均有可验证、不可伪造的恢复行为。
9. Mock 演示全程不向公网发送真实会话数据。
